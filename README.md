A local web chatbot that recommends video games based on user preferences. The project is built on **Spring AI 2.0.1** using the **RAG** (Retrieval-Augmented Generation) approach: answers are generated by an LLM based on a local knowledge base, not "from the model's head". The chat works in **streaming mode** via **`SseEmitter`** (Server-Sent Events).

---

## 📌 About the Project

**Project goal** — practical study of working with large language models (LLMs) and the RAG approach.

**Practical use** — a locally deployed chatbot with a web interface that, upon user request (e.g., *"recommend a CRPG with good Steam Deck optimization"*), provides a list of suitable games with justification.

**Key idea:** all work happens **offline**, on your own machine.

## 🧠 How It Works

### Knowledge indexing (offline)

```
knowledgebase/*.txt ──▶ file-loader ──▶ mxbai-embed-large (Ollama)
                                              │
                                              ▼
                                     PostgreSQL + pgvector
                                    (embeddings + metadata)
```

### User request processing (online, streaming via SSE)

```
┌──────────────┐
│     User     │
│  (Thymeleaf) │
└──────┬───────┘
       │  GET /chat-stream/{chatId}
       │  (EventSource)
       ▼
┌───────────────────────────────────────────────────────────┐
│                    Spring AI Pipeline                     │
│                                                           │
│  1. System prompt forms the base context                  │
│  2. ExpansionQueryAdvisor  ── expands the query,          │
│                              adds related data            │
│  3. RagAdvisor + BM25RerankEngine ── retrieval + rerank   │
│                              found documents              │
│                              are mixed into context       │
│  4. ChatClient (stream) → qwen2.5:7b (Ollama)             │
│                                                           │
└──────────────────────────┬────────────────────────────────┘
                           │  tokens (Server-Sent Events)
                           ▼
              ┌──────────────────────────┐
              │  SseEmitter → browser    │
              │  (incremental output)    │
              └──────────────────────────┘
```

## 📚 Data

The dataset is a set of **text files** in the `src/main/resources/knowledgebase/` directory, one file per release year (e.g., `2000.txt`, `2001.txt`, ..., `2026.txt`).

Game information is stored in one line in the format:

```
Title - genres: <genres> - age: <year> - rating: <Metacritic> - steamdeck rating: <0-5> (<ProtonDB level>)
```

### Example line (`2000.txt`)

```
Baldur's Gate II: Shadows of Amn - genres: CRPG - age: 2000 - rating: 95 - steamdeck rating: 5 (platinum)
```

### Data Sources

- **[Metacritic](https://www.metacritic.com/)** — game ratings for games released from 2000 to 2026.
- **[ProtonDB](https://www.protondb.com/)** — compatibility and performance of games on **Steam Deck** (Platinum / Gold / Silver / Bronze / Borked).

## ⚠️ Known Issues

The project is educational, and the following limitations are currently being worked on:

- **Genre confusion.** The model sometimes assigns a game to the wrong genre (e.g., classifies a shooter as an RPG) if the query contains overlapping keywords. The reason is imperfect embeddings and insufficient accuracy of structural filtering at the retrieval stage.
- **Sorting by rating is unstable.** When explicitly asked to "sort by Metacritic", the model does not always maintain the order: the RAG context does not contain an explicit sorting rule, and the LLM tends to "rearrange" results according to its own logic. Plans include adding a structural filtering layer (SQL query on metadata) **before** calling the LLM.

### Roadmap

- [ ] Hybrid retrieval: vectors + structural filters on metadata (genre, year, rating, steamdeck rating)
- [ ] Separate tool/function for sorting and numeric filtering of results
- [ ] UI improvement: dialogue history, game cards, links to Metacritic/ProtonDB
